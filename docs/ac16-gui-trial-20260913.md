# AC16 production GUI trial — 2026-09-13

The GitHub-built Linux CPU and CUDA AppImages passed complete frame-to-RF-to-GUI
trials using the selected AC16 v4 model. Each 60-second RTL-SDR trial recovered
60/60 correctly ordered GOPs and displayed all 600 frames. The Pluto receive
check recovered and displayed 100/100 frames. There were no pipeline errors.

## Hardware and method

The host uses an AMD Ryzen 9 9950X and RTX 4090, NVIDIA driver 595.71.05.
CPU trials selected CPUExecutionProvider with CUDA hidden and eight inference
threads. The CUDA trial selected CUDAExecutionProvider with two CPU threads.
Pluto transmitted finite buffers at nominal 2.4 MS/s, 439 MHz waveform center,
−10 dB TX hardware gain and active waveform RMS 0.2. RTL serial 1001 received
at 960 ksample/s and 37.2 dB gain. Pluto receive used 2.4 MS/s and 40 dB gain.
Automatic received-IQ frequency correction was enabled. The radios were about
ten feet apart. Broken RTL 1002 was excluded.

The fixture supplied the same 600 RGB frames from 30 training-disjoint validation
clips at 10 fps, followed by ordinary GUI encode, modulation, radio TX/RX,
demodulation, confidence-aware decode and displayed-frame callbacks. Source SHA:
`85f201e2c51902c864e5f2dcd15dea2aa4ddbe51ff8796a47092cc10125d9fdb`.
Validation clips participated in checkpoint selection; they are not an untouched
test partition. Physical camera acquisition and display scan-out were excluded.
The receiver received no source pixels, source timing or source latents. Latent
correspondence and chronology were scored after reception. The waterfall displays
actual complex receive IQ. The test requires both full displayed-frame counts
and correct, high-fidelity payload correspondence.

## Checks and limits

344 local tests passed; optional native-checkpoint and FT8-runtime tests were skipped. Linux and
Windows CI and all four package builds passed. Tests cover exact AC16 wire
roundtrips, forced early/late preamble ambiguity with streamed and batched input,
GPU/DirectML provider selection, bounded IQ handling, short-clip playout and
transmit shutdown after success, cancellation and driver/source errors.

Artifact trials exposed and fixed TX buffering, premature automatic tuning,
Linux ABI compatibility and repeated-preamble GOP-phase errors before release.
AC16 startup now checks the received mode-header boundary and neighboring
preamble repetitions; periodic payload pilots alone cannot establish GOP phase.
Initial failed attempts are retained in the local evidence directory. A parallel
large artifact download coincided with a midstream receive gap; final performance
trials were repeated with bulk transfers and builds stopped. The driver does not
expose a sample-loss counter, so the cause of that gap is not established.

The figures above describe this strong local link and this host. Windows SDR
operation requires vendor libiio/rtl-sdr runtimes and USB drivers, and was not
physically tested here. Linux packages bundle the native SDR libraries and use
Ubuntu 22.04 as their ABI baseline. An independent final readback verifies Pluto
TX powered down and its gain returned to −89.75 dB; no RTL capture process remains.
